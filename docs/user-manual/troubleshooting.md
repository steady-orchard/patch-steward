# Troubleshooting

[Manual contents](README.md) · [Installation](installation.md) · [Configuration](configuration.md)

Only the scaffold, the policy module, the submission contract check, `steward policy`, the deterministic part of `steward preflight`, `steward screen` at contract level, `steward report`, and a GitHub-hosted skeleton in observe mode at contract level, verified only on dedicated test-bed repositories, are implemented. Product troubleshooting below describes failure paths in the design, not observed errors from a released product; rows that name failure codes of `gate` or `publish` describe the GitHub-hosted skeleton as implemented.

## Scaffold and availability

| Symptom                                                                                                           | Cause supported by the sources                                                                                                                                                                                                                                                                                                                                                                                                                              | Action                                                                                                                                                                                |
| ----------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| No `steward` command on the path, or no screening after setup                                                     | The CLI package is private and unpublished; only `steward policy`, `steward preflight`, `steward screen` (contract level, local only), and `steward report` are implemented, and GitHub-hosted screening exists only as a skeleton in observe mode at contract level on dedicated test-bed repositories, not installable in a target repository.                                                                                                            | Run `pnpm build`, then `node packages/cli/dist/main.js policy`. Product installation remains blocked on implementation.                                                               |
| Build passes without verifying tests                                                                              | Package tsconfigs exclude `**/*.test.ts` from the build.                                                                                                                                                                                                                                                                                                                                                                                                    | Run `pnpm typecheck` for types and `pnpm test` for behavior.                                                                                                                          |
| `steward policy` exits `2` with `git.ref-unresolvable`                                                            | The ref (default `origin/HEAD`) does not exist in the local repository; the command never fetches.                                                                                                                                                                                                                                                                                                                                                          | Run `git remote set-head origin --auto` or `git fetch`, pass an existing ref with `--ref`, or check a file with `--file`.                                                             |
| `steward policy` exits `1` with `git.policy-directory-missing` or `git.entry-missing`                             | The commit has no `.github/patch-steward/` directory or no `policy.yml` in it.                                                                                                                                                                                                                                                                                                                                                                              | Commit the policy on that branch, or check a local file with `--file`.                                                                                                                |
| `steward policy` exits `1` with `policy.*` or `yaml.*` errors                                                     | The policy is invalid; each error names its key path and, when known, line and column.                                                                                                                                                                                                                                                                                                                                                                      | Correct each reported key; the codes are explained in the [configuration reference](configuration.md).                                                                                |
| Warning `policy.llm-model-placeholder`                                                                            | `llm.model` is still the template placeholder `replace-with-model-id`.                                                                                                                                                                                                                                                                                                                                                                                      | Set a real model id. The policy stays valid, but a run that reaches a model stage with the placeholder ends `inconclusive`.                                                           |
| `steward preflight` exits `1`                                                                                     | The draft does not meet the contract (`needs-changes`) or needs a maintainer decision (`uncertain`).                                                                                                                                                                                                                                                                                                                                                        | Follow the numbered requests; see [Submission corrections](#submission-corrections-proposed).                                                                                         |
| `steward preflight` exits `2` with `preflight.no-upstream`                                                        | No `--repo` was given, and neither the `upstream` nor the `origin` remote is a GitHub repository.                                                                                                                                                                                                                                                                                                                                                           | Pass `--repo owner/name`.                                                                                                                                                             |
| `steward preflight` exits `2` with `preflight.base-unresolvable`                                                  | The base ref (by default the local remote-tracking ref of the upstream default branch) does not exist locally; the command never fetches.                                                                                                                                                                                                                                                                                                                   | Fetch the upstream remote, or pass `--base <ref>`.                                                                                                                                    |
| `steward preflight` exits `2` with `preflight.head-unresolvable`                                                  | `HEAD` names no commit.                                                                                                                                                                                                                                                                                                                                                                                                                                     | Commit the change and rerun; uncommitted changes are never read.                                                                                                                      |
| `steward preflight` exits `2` with `preflight.repository-unavailable`                                             | The repository does not exist, or it is private and no token was found or the token cannot read it.                                                                                                                                                                                                                                                                                                                                                         | Set `GH_TOKEN` or `GITHUB_TOKEN`, or log in with `gh auth login`.                                                                                                                     |
| `steward preflight` exits `2` with `preflight.token-rejected` or `auth.token-invalid`                             | GitHub rejected the token, or a token variable holds a value that is not a usable token.                                                                                                                                                                                                                                                                                                                                                                    | Replace or unset the variable; a rejected token never falls back to unauthenticated reads.                                                                                            |
| `steward preflight` exits `2` with `preflight.policy-invalid`                                                     | The upstream repository's published policy is invalid; the default checklist is never substituted.                                                                                                                                                                                                                                                                                                                                                          | Report it to the maintainers; the printed errors name each key.                                                                                                                       |
| `steward preflight` exits `2` with a `preflight.draft-*` code                                                     | The draft path is wrong or not a file, the draft exceeds 262144 bytes or GitHub's 65536-character body limit, or it is not UTF-8.                                                                                                                                                                                                                                                                                                                           | Correct the path or the file.                                                                                                                                                         |
| `steward preflight` exits `2` with a `github.*` code, such as `github.rate-limited`                               | A GitHub read failed; without a token the rate limit is lower.                                                                                                                                                                                                                                                                                                                                                                                              | Retry later, or provide a token.                                                                                                                                                      |
| Warning `github.unauthenticated`                                                                                  | No token was found, so public reads are unauthenticated.                                                                                                                                                                                                                                                                                                                                                                                                    | Set `GH_TOKEN` or `GITHUB_TOKEN`, or log in with `gh`, to raise the rate limit.                                                                                                       |
| `steward preflight` exits `3`                                                                                     | A required read failed (for example the linked issue could not be read), so the disposition is `inconclusive`; each `inconclusive <cause> <code>: <message>` line names it.                                                                                                                                                                                                                                                                                 | Retry when GitHub is reachable, or provide a token.                                                                                                                                   |
| `steward screen` exits `1` with `outcome: needs-changes`                                                          | The submission contract failed.                                                                                                                                                                                                                                                                                                                                                                                                                             | Follow each `request R<n>` line.                                                                                                                                                      |
| `steward screen` exits `1` with `screen.policy-file-invalid`                                                      | The `--policy-file` fails validation.                                                                                                                                                                                                                                                                                                                                                                                                                       | Correct the reported keys (see `steward policy --file`).                                                                                                                              |
| `steward screen` exits `3` with `cause: stage-incomplete`                                                         | Expected at contract level: no screening stage (reference verification, claim validation, reproduction, fix verification, regression, challenge) is implemented yet, so a submission that meets its contract cannot pass.                                                                                                                                                                                                                                   | Read the report's "What would change the outcome"; other causes (for example `github-unavailable`, `attachment-fetch-failed`) name a read that failed and can be rerun when resolved. |
| `steward screen` exits `2` with `screen.policy-missing`                                                           | The upstream default branch has no `.github/patch-steward/policy.yml`; the default checklist is never used for screening.                                                                                                                                                                                                                                                                                                                                   | Pass `--policy-file <path>` (the run is then non-authoritative).                                                                                                                      |
| `steward screen` exits `2` with `screen.policy-invalid`                                                           | The published policy is invalid.                                                                                                                                                                                                                                                                                                                                                                                                                            | Report it to the maintainers, or use `--policy-file`.                                                                                                                                 |
| `steward screen` exits `2` with `screen.no-upstream`                                                              | No `--repo` and no GitHub `upstream` or `origin` remote.                                                                                                                                                                                                                                                                                                                                                                                                    | Pass `--repo owner/name`.                                                                                                                                                             |
| `steward screen` exits `2` with `screen.repository-unavailable`, `screen.token-rejected`, or `auth.token-invalid` | As for `steward preflight`: a missing or private repository without a usable token, a rejected token, or an unusable token variable.                                                                                                                                                                                                                                                                                                                        | Set a valid token, or replace or unset the variable.                                                                                                                                  |
| `steward screen` exits `2` with `screen.evidence-dir-unavailable`                                                 | No home directory to derive the default evidence directory.                                                                                                                                                                                                                                                                                                                                                                                                 | Pass `--evidence-dir <dir>`.                                                                                                                                                          |
| `steward screen` exits `2` with `screen.evidence-write-failed`                                                    | The run evidence could not be written, so no report exists; the next error line names the cause, for example `evidence.redaction-invalidated` (a credential-like string, such as credentials in an attachment URL, was redacted inside the snapshot, which then no longer matches its hash), `evidence.too-large` (records and report exceed `limits.evidence.run_bytes`), `evidence.write-failed` (the directory is not writable), or `redaction.timeout`. | Choose a writable `--evidence-dir`, raise the policy limit within its hard maximum, or ask the author to remove credentials from the submission.                                      |
| Warning `screen.evidence-inside-checkout`                                                                         | `--evidence-dir` lies inside the current git work tree.                                                                                                                                                                                                                                                                                                                                                                                                     | Move it outside, or never commit the run directories.                                                                                                                                 |
| `steward report` exits `1` with `report.evidence-invalid`                                                         | The run directory fails verification (a file changed, added, or removed, a record or hash mismatch, or stored text with a control or format character); the detail error names the file.                                                                                                                                                                                                                                                                    | Rerun `steward screen` instead of repairing evidence.                                                                                                                                 |
| `steward report` exits `2` with `report.run-unreadable`                                                           | The path is not a readable run directory.                                                                                                                                                                                                                                                                                                                                                                                                                   | Pass the path printed after `run directory:`.                                                                                                                                         |
| Warning `report.metrics-missing`                                                                                  | The run's metrics file under `metrics/<YYYY-MM>/` is missing (for example the run directory was copied without it).                                                                                                                                                                                                                                                                                                                                         | None; the report still prints.                                                                                                                                                        |
| `steward report` exits `3`                                                                                        | The stored run is `inconclusive` (see `stage-incomplete` above).                                                                                                                                                                                                                                                                                                                                                                                            | See the `stage-incomplete` action above.                                                                                                                                              |
| `-h` prints an error (`usage.unknown-command`)                                                                    | Only long flags exist.                                                                                                                                                                                                                                                                                                                                                                                                                                      | Use `steward help` or `steward --help`.                                                                                                                                               |
| A relative TypeScript import lacks its required extension                                                         | The scaffold uses ESM, `nodenext`, and `verbatimModuleSyntax`.                                                                                                                                                                                                                                                                                                                                                                                              | Use a `.js` suffix as in `import { greet } from './index.js'`.                                                                                                                        |
| Formatting check fails                                                                                            | Prettier checks Markdown as well as source; its ignore list excludes only the documented paths.                                                                                                                                                                                                                                                                                                                                                             | Run `pnpm format`, inspect the changes, and rerun `pnpm format:check`.                                                                                                                |
| No Codecov upload                                                                                                 | The upload job runs only from `develop` and uses `CODECOV_TOKEN`.                                                                                                                                                                                                                                                                                                                                                                                           | Check the branch and repository secret; use `pnpm coverage` for a local report.                                                                                                       |
| No release tag or merge into `develop`                                                                            | CD triggers only for `package.json` changes on `master`; an existing version tag skips both tag creation and the merge.                                                                                                                                                                                                                                                                                                                                     | Check the triggering change and package version. Both remote branches must exist and repository rules must allow the operations.                                                      |

## Submission corrections (Proposed)

Begin with the report's numbered requests and "what would change the outcome."
Missing contributor evidence is `needs-changes`; failure of steward-side work is
`inconclusive`.

| Symptom                                                    | Documented cause                                                                                                                                                                                                                                                                                   | Correction or next decision                                                                                                                      |
| ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| Template rejected                                          | Unrecognized structure where free-form submissions are disallowed (`submission.unstructured`), or a duplicated field (`submission.field-duplicate`).                                                                                                                                               | Use the installed form or template, keep its labels, headings, and marker line, and correct the reported fields; the request links the template. |
| Attachment exceeds limits                                  | An attachment breaks a rule (`submission.attachment-violation`; the detail names `count`, `destination`, `scheme`, `userinfo`, `format`, `file-bytes`, `total-bytes`, `redirects`, `archive`, or `decompressed-bytes`).                                                                            | Supply compliant files on an approved destination in an approved format.                                                                         |
| Required field missing                                     | A field the policy requires is absent or trivial, such as `_No response_` or `N/A` (`submission.field-missing`).                                                                                                                                                                                   | Fill in the named section of the body.                                                                                                           |
| Category or linked issue rejected                          | The `Category` value is not exactly one category (`submission.category-missing`, `submission.category-invalid`), or the `Linked issue` value is not exactly one existing issue in the same repository (`submission.linked-issue-missing`, `submission.linked-issue-invalid`).                      | Edit the named section: one category, and one issue such as `#123`.                                                                              |
| Required attachment could not be fetched                   | A required attachment's fetch failed (DNS, a non-public address, TLS, a timeout, or an error status, including an attachment that needs authentication): the run is `inconclusive` (`attachment-fetch-failed`). For an optional attachment it is the advisory `submission.attachment-unavailable`. | Attach the file so that it is publicly readable, or include its content as a fenced code block.                                                  |
| Missing reference, reproduction, or test declaration       | The category requires it.                                                                                                                                                                                                                                                                          | Edit the specified body field or commit the required test; a conversation comment alone does not satisfy these requests.                         |
| `proposal-required`                                        | Feature/design PR lacks accepted intent under `propose-first`.                                                                                                                                                                                                                                     | Link an accepted proposal, obtain `/steward accept` on the PR, or obtain a scoped waiver.                                                        |
| Passing proposal still waits for acceptance                | `proposal-pending` passes the submission contract, not the intent decision.                                                                                                                                                                                                                        | A maintainer must accept or decline it; nothing is requested from the author.                                                                    |
| Base test fails but before-and-after verification is unmet | Failure is compilation/missing-symbol failure rather than the claimed behavior.                                                                                                                                                                                                                    | Supply behavioral before-evidence; a separate reproduction may be accepted if policy permits it.                                                 |
| Reproduction does not demonstrate the claim                | It fails to reproduce in the claimed supported environment.                                                                                                                                                                                                                                        | Correct the reproduction, command, environment information, or claimed behavior. Unrelated setup failures remain inconclusive.                   |
| `fabricated-reference`                                     | An authoritative reference is definitively absent at the claimed revision.                                                                                                                                                                                                                         | Correct the reference or provide a verifiable basis. Network failures are unverified references, not fabrication.                                |
| Tests pass but result is `uncertain`                       | Category or intent ambiguity (`submission.category-mismatch`, `submission.category-enforced-ambiguity`), execution-sensitive path changes (`submission.execution-sensitive-change`), or a diff too large to classify (`submission.diff-too-large`) need a maintainer decision.                     | Review the uncertainty and relevant changes with a maintainer; passing tests alone cannot resolve it.                                            |
| Proposal acceptance disappeared after editing              | Issue content hash or PR claim scope/target changed.                                                                                                                                                                                                                                               | Obtain renewed acceptance. Implementation-only pushes with unchanged PR scope retain intent acceptance but rerun technical screening.            |

## Waiting states and checks (Proposed)

| Symptom                                                    | Documented cause                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | Action                                                                                                                                                                                          |
| ---------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `queued`, pending check                                    | Approximate daily or per-author concurrency cap reached, counted from the Actions run list by the wrapper run name. The run commits ownership and records a waiting run directory with `waiting.json` (reason, counts, limits, arrival time).                                                                                                                                                                                                                                                                                                                                       | The maintenance workflow is designed to restart queued work in arrival order within caps, refreshing inputs; it does not exist yet, so a queued run of the GitHub-hosted skeleton stays queued. |
| `awaiting-approval`, pending check                         | `llm.admission: maintainer-approved` holds an author without prior merged work.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | A maintainer posts `/steward rerun` to admit this submission. An author rerun or manual label cannot admit it.                                                                                  |
| Shared-head blocker despite an override or advise mode     | Multiple open PRs share one head commit.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            | Push a distinct commit or close the other PRs. Required/enforced checks use `action_required`; an optional advise-only check fails. This cannot be overridden.                                  |
| Run is `superseded`                                        | Snapshot changed or a newer committed owner exists; the run's supersession record names the reason (`newer-owner` or `snapshot-changed`).                                                                                                                                                                                                                                                                                                                                                                                                                                           | Consult the replacement. The old run retains evidence and may cancel only its own pending check.                                                                                                |
| The run ends with disposition `duplicate` and no evidence  | The event's snapshot hash and policy revision equal those of the newest committed owner (for example a title-only edit, or an unchanged edit by the App), so `gate` kept that owner: no ownership artifact, cancellation, cap evaluation, or evidence; the gate job summary names the kept owner.                                                                                                                                                                                                                                                                                   | None. Edit the body or rerun the workflow to screen again; reopening always rescreens.                                                                                                          |
| `gate` fails and nothing is published                      | A failure before commitment, named in the gate job summary: `gate.event-invalid` (the event payload or runner environment does not match), `app-auth.credentials-invalid` (the Environment secrets are missing or unusable), `gate.policy-missing` or `gate.policy-invalid` (no valid policy on the default branch), `gate.repository-gate-unsupported` (a category is in `advise` or `enforce`, which needs check runs), `ownership.listing-unavailable` or `ownership.record-invalid`, or `caps.run-list-unavailable`. It supersedes nothing, and no evidence exists for the run. | Fix the named cause (policy, Environment secrets, or App installation) and rerun the workflow.                                                                                                  |
| `publish` fails after `gate` committed                     | `evidence.store-conflict` (the branch kept moving), `evidence.store-not-append-only`, `evidence.readback-mismatch`, `pipeline.handoff-invalid` or `pipeline.handoff-binding`, or a store installation or permission failure leaves no evidence and no summary outcome. `publish.freshness-unknown` means the evidence commit exists, but the ownership listing or the recapture was unavailable or ambiguous, so publication failed without a supersession record.                                                                                                                  | Restore store access or the App installation, then rerun the whole workflow; rerunning only `publish` after its evidence commit succeeded fails as not append-only.                             |
| New run cannot create its required check                   | `gate` cannot create a fresh App check.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | Inspect App credentials and check permissions. The run stops before ownership commitment and reports that the previous certification still stands.                                              |
| Check stays pending after job failure                      | `gate`/`publish` failed, or cancellation prevented publication.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | Inspect those jobs and restore the missing service/credential/store. Maintenance marks stale checks `action_required`; a fresh run creates a new check.                                         |
| Neutral check despite a non-pass report                    | Category is advised or outside enforcement.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | Read the mode and summary. Neutral does not mean pass; waiting/shared-head exceptions still block.                                                                                              |
| Merge-queue entry has no required check                    | Missing or failed relay did not start group verification.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | Inspect the relay and default-branch screening workflow. The queue entry waits until timeout; no success is inferred.                                                                           |
| Merge-queue entries enqueued by automation always time out | The automation enqueued them with a job `GITHUB_TOKEN`; events caused by that token start no workflow run, so no relay run starts and the required check never arrives.                                                                                                                                                                                                                                                                                                                                                                                                             | Enqueue through a person or with a GitHub App token instead. The entry leaves the queue at its timeout; nothing merges without the required check.                                              |
| Earlier success no longer counts on the same commit        | A fresh App check for a newer run superseded it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | Follow the latest run and its snapshot.                                                                                                                                                         |

> **[NEEDS INPUT]** Schedule intervals and exact maintenance recovery inputs are not
> specified. Daily caps, per-author concurrency, and the stale-check timeout are
> policy limits (`limits.caps.daily_runs`, `limits.caps.per_author_concurrent_runs`,
> `limits.stale_check_minutes`).

## Infrastructure and inference (Proposed)

| Symptom                                             | Documented cause                                                                                                                                                                                                                                                                                                                       | Action                                                                                                                                                                                                                                                                                                     |
| --------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Every run is `inconclusive` after a policy change   | Trusted policy fails validation.                                                                                                                                                                                                                                                                                                       | Validate the policy with `steward policy`, then correct it through maintainer review; unknown keys, out-of-bounds limits, and undeclared references are rejected. No fallback policy is substituted.                                                                                                       |
| Inference fails before execution                    | Missing/unknown provider, unusable credential, disabled Copilot policy (unverified; `probes/findings.md` PA08.7), or capability mismatch. A disabled policy shows as the CLI's "Access denied by policy settings" or as an SDK HTTP 403 `authorization` error that reads like an expired credential.                                   | Check the selected adapter/model/auth pairing and Environment or job permissions; rerun the installation capability probe after correcting setup. Through the SDK a disabled policy and an unusable credential look alike; for an organization-owned repository an organization owner confirms the policy. |
| Copilot inference cannot run in Actions             | The wrapper grants less than the pinned reusable workflow's jobs request, for example no `copilot-requests: write`, so the whole run fails at startup with no job, check, or report; or the required organization policy is disabled (unverified; `probes/findings.md` PA08.7) and the CLI reports "Access denied by policy settings". | Restore the wrapper permissions that `steward init` writes, equal to the pinned reusable workflow's job permissions, and rerun the installation self-test; or have an organization owner enable the policy.                                                                                                |
| Model unavailable or retired                        | The configured model cannot serve the required work.                                                                                                                                                                                                                                                                                   | Maintainers must select a usable supported model in trusted policy; no automatic substitution occurs.                                                                                                                                                                                                      |
| Refusal or malformed structured output              | Required model output could not be obtained or validated within repair limits.                                                                                                                                                                                                                                                         | Review the recorded cause; maintainers may rerun or make a scoped decision. It cannot be treated as pass.                                                                                                                                                                                                  |
| Rate-limit or budget failure                        | Bounded retries or cumulative allowance exhausted.                                                                                                                                                                                                                                                                                     | Inspect usage and provider controls. One automatic rerun is allowed for transient causes within the daily cap; permanent/exhausted failures remain inconclusive.                                                                                                                                           |
| Inference spends more than expected in observe mode | Observe runs the full pipeline; Copilot credit caps are soft.                                                                                                                                                                                                                                                                          | Review provider spending limits, cumulative usage, daily caps, and the optional admission rule. Mode alone is not a spending control.                                                                                                                                                                      |
| Environment failure or missing platform coverage    | Runner/image unavailable, baseline cannot be produced, or required platform lacks admissible results.                                                                                                                                                                                                                                  | Restore the declared environment and matching baseline/coverage. Linux results cannot stand in for a missing Windows baseline.                                                                                                                                                                             |
| Reproduction needs a network or external service    | Execution network is disabled unless policy allows the necessary setup/services.                                                                                                                                                                                                                                                       | Reduce it to a self-contained reproduction; allowed-service configuration remains an open decision.                                                                                                                                                                                                        |
| Evidence cannot be written                          | Store is missing, unwritable, or bounded write retries fail.                                                                                                                                                                                                                                                                           | Restore store access and App installation/permissions. Admission cannot publish success without durable evidence.                                                                                                                                                                                          |

No job should combine App and inference credentials to work around a permission
failure. Submitted code must remain in credential-free containers; running it on
the host is not a documented recovery path.

## Reports, commands, and dashboard (Proposed)

| Symptom                                                      | Documented cause                                                                                                          | Action                                                                                                                  |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| No report, label, or draft promotion                         | Category is in `observe`.                                                                                                 | Read evidence and Actions summaries. Follow the ordinary manual readiness/review process.                               |
| Command has no effect                                        | Unauthorized user, review comment, or edit of an existing command comment.                                                | Post a permitted command at the start of a new issue/PR conversation comment.                                           |
| Manual label does not accept a proposal or override a result | Labels are outputs, not authenticated actions.                                                                            | Use the applicable maintainer command.                                                                                  |
| Explanation did not trigger a rerun                          | Response did not cite/address the numbered explanation request, or supplied a field/test that belongs in the body/commit. | Follow the request's destination; the steward's single follow-up identifies corrections.                                |
| Local pass does not satisfy the required check               | Preflight is a claim; maintainer local output is attributed, not authoritative admission.                                 | Use official Actions screening. A maintainer may cite local evidence in a scoped override.                              |
| Report exists but dashboard is missing                       | Pages is unavailable or public export is disabled.                                                                        | Use the durable evidence link and Actions summary. Pages failure degrades the dashboard, not evidence-backed screening. |
| Private evidence absent from the browser                     | Version 1 browser cannot directly read private stores; public export needs approval.                                      | Use private evidence/Actions summaries or the explicitly authorized public subset.                                      |
| Cost is missing                                              | Provider did not report usable usage/cost information.                                                                    | Treat it as unknown, not zero; the report body does not contain per-run cost.                                           |
